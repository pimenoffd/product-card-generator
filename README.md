# Генератор карточек товаров

Локальный прототип создаёт черновик карточки измерительного прибора из JSON через OpenRouter. Характеристики копируются из входа; текст модели требует проверки человеком.

## Установка и запуск

Нужен Python 3.12 или новее и ключ OpenRouter. Текущий снимок зависимостей `requirements.lock` получен на Python 3.13; CI настроен на Python 3.13. Для установки актуальных совместимых версий вместо снимка используйте `pip install -e '.[dev]'`.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock
pip install --no-deps -e .
cp .env.example .env
```

В `.env` укажите `OPENROUTER_API_KEY` и `OPENROUTER_MODEL`, например `google/gemini-2.5-flash`. Запустите:

```bash
streamlit run app.py
```

Измените JSON в форме и нажмите «Создать карточку». Результат можно скачать в JSON или Markdown. Для неполных данных или при несоблюдении требований к длине появляется предупреждение. Пример в форме взят из ТЗ и не подтверждён по каталогу.

## Проверки

```bash
pytest -q
ruff check .
ruff format --check .
```

Тесты не требуют API-ключа или доступа в сеть.

## Решения и ограничения

Системный промпт требует опираться на исходные факты и отмечать недостающие данные. OpenRouter вызывается со структурированным ответом JSON Schema; поддержка параметров требуется при маршрутизации. Код проверяет длину заголовка и описания, количество запросов и наличие коммерческого блока, при необходимости выполняет одну повторную генерацию. При недостатке фактов короткое описание сохраняется с предупреждением.

Статус `valid` отражает только автоматические проверки, не подтверждает достоверность свободного текста. Модель может допустить фактические ошибки или выполнить инструкции из входного текста: перед использованием проверьте каждый факт. Поддержка модели зависит от доступных endpoints OpenRouter. При генерации JSON сохраняет метаданные: модели ответа по попыткам (или запрошенная модель, если API не сообщил её ID), версию и хеш промпта, дату UTC, длительность и суммарные входные/выходные токены. Если API не сообщил расход хотя бы одной попытки, итоговое значение остаётся неизвестным (`null`).

## Примеры и оценка качества

- `data/examples/catalog/` — пять входных JSON с выборочными характеристиками из карточек каталога; ссылки и оговорки приведены рядом.
- `demo/` — два сохранённых результата live-прогона с входами и метаданными генерации. Это примеры, требующие проверки, а не эталоны качества.
- `evals/cases.json` — восемь случаев для оценки, включая пустые поля, противоречия и посторонние инструкции. Подробнее: [методика оценки](evals/README.md).

Проверить сохранённые результаты без ключа:

```bash
python -m product_cards.evaluate --cases demo/cases.json --results demo/results.json --output evals/reports/demo-report.json
```

Выполнить живой прогон восьми случаев через настроенную модель (до 16 платных запросов):

```bash
python -m product_cards.evaluate --live
```

Live-отчёт по умолчанию сохраняется в `evals/reports/report.json`, а приведённая выше команда для сохранённых результатов — в `evals/reports/demo-report.json`. Задайте другой путь через `--output`, чтобы сохранить отдельный отчёт. Проверяются формат, сохранность характеристик, новые числа и типовые служебные фразы. Эвристики не заменяют ручную оценку. Код завершения 0 означает отсутствие ошибок обработки, а не одобрение содержания.

В прогоне 7 ноября 2026 года модель `google/gemini-2.5-flash` обработала все 8 случаев без ошибок API, с двумя попытками на каждый. Все описания оказались короче требуемых 800–1200 символов; в трёх случаях число поисковых запросов тоже не соответствовало требованиям. Во всех случаях характеристики сохранились, эвристики не обнаружили новых чисел и типовых служебных фраз. Это не заменяет ручной проверки фактов и устойчивости к посторонним инструкциям. По данным отчёта, суммарно использовано 5146 входных и 2360 выходных токенов, суммарная длительность генерации — 28,064 с.

## Архитектура и воспроизводимость

`app.py` отвечает за форму и экспорт; `models.py` — за контракты; `llm.py` — за OpenRouter и промпт; `service.py` — за проверки, одну корректирующую попытку и метаданные; `evaluate.py` — за независимую оценку. LLM генерирует только текстовые поля, таблица характеристик собирается из исходных значений. Длительность включает обе попытки, но не работу с формой.

GitHub Actions запускает тесты, Ruff и обработку сохранённых примеров без API-ключа.

## Возможности дальнейшего развития

- **Пакетная обработка фида.** Выбирать позиции по идентификаторам, моделям и другим полям; формировать карточку и отчёт об ошибках для каждой позиции. Для больших файлов читать XML постепенно и ограничивать число одновременных запросов.
- **Интеграция через FastAPI.** Добавить HTTP API поверх существующего сервиса генерации с валидацией входа, структурированными ошибками и документацией для внешних систем.
- **Оценка и выбор модели.** Расширить набор случаев, собрать обратную связь контент-менеджеров и сравнить модели и версии промпта по точности технических данных, качеству текста, времени и стоимости. Текущая недорогая модель — отправная точка для такого сравнения.
- **Проверка технических утверждений.** Сопоставлять значения и единицы измерения во всём тексте с исходными данными, отмечать противоречия и показывать менеджеру места, требующие проверки. Существующая проверка новых чисел в отчёте — только эвристика.
- **Поиск недостающих сведений.** Дополнять вход данными из локальных технических паспортов и, при необходимости, проверенных интернет-источников, например сайта производителя. Сохранять ссылки на источники и выделять сведения для подтверждения перед публикацией.
- **Работа с черновиком.** Добавить редактирование карточки перед экспортом и повторную проверку ограничений после правок.
- **Интеграция с системой публикации.** Передавать подготовленные карточки напрямую в систему управления товарами как черновики для проверки и последующей публикации менеджером.
- **Изображения.** При необходимости генерировать иллюстрации, явно обозначая их как иллюстративные; для точного изображения конкретной модели использовать подтверждённые материалы производителя.
