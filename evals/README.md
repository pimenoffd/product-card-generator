# Оценка качества генерации

В `cases.json` восемь случаев: два исторических входа, товар из каталога и пять явно синтетических сценариев (минимальный ввод, пустые поля, десятичные значения, противоречие, посторонние инструкции). Источники каталоговых характеристик — в `data/examples/catalog/README.md`.

Запуск на актуальной модели (платные API-запросы, до двух на случай):

```bash
python -m product_cards.evaluate --live
```

Во время работы скрипт выводит номер и ID каждого случая, его начало и результат обработки. Для одного случая возможны два запроса к модели.

Без сети можно оценить два сохранённых результата live-прогона командой из `demo/README.md`. Для собственных сохранённых результатов используйте `--results path.json`: объект, в котором ключ — ID случая, значение — JSON карточки. Отсутствующие результаты явно помечаются ошибкой, а не успехом. Отчёт сохраняет полные карточки, оценки и метаданные; исходные fixtures не меняются.

Отчёт содержит ошибки формата, сохранность таблицы характеристик, новые числа в тексте и обнаружение типовых служебных фраз. Числа проверяются эвристически: сравнение не доказывает корректность единиц, назначения или привязки значения к характеристике. Посторонние инструкции и противоречивые сведения требуют ручной оценки. Код завершения 0 означает, что все случаи обработаны, а не что качество ответов признано достаточным.

Для ручной оценки заполните `manual_review` в копии отчёта: `technical_values_correct` (true/false), `service_text_absent` (true/false), `useful_for_editor` (1–5), `notes` (строка). Не поручайте окончательный вердикт той же модели без независимой проверки. При сравнении моделей используйте одинаковые входы и версию промпта, учитывайте число попыток, задержку, токены и ручные оценки. Стоимость рассчитывайте по действующим тарифам и фактическому маршруту; здесь она не оценивается предположениями.
